# 1. Record architecture decisions

**Status:** accepted

## Context

Decisions that shape a system are usually made once, in a conversation, and
then re-litigated every few months by whoever inherits the code — often
reversing them without knowing what they were for.

## Decision

Significant architectural decisions are recorded here as short numbered
documents: the context, the decision, and the consequences we accepted. A
record is never edited once accepted; a superseding record is added instead and
the old one is marked.

## Consequences

New contributors can find out why the system is the way it is without asking.
Reversing a decision means writing down why the original reasoning no longer
holds, which is a useful bar to clear.
